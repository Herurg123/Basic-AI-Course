# Author notes — M06-L04

> **Не показывать ученику до завершения соответствующей независимой попытки.**
>
> Файл хранит скрытую рубрику, red-team правила и alternate/re-check scenarios. Это не новый Asset ID.

## 0. Роль урока

`M06-L04` завершает на INDEPENDENT level 3:

`A1, A2, B9, B10, B11, B12, C1, C2, C3`.

B0–B8 только REUSE по ситуации. Нового метода здесь не вводится.

Полный B10 собирается из:

1. ранее принятого `M04-L03-C02` — проверка по собственному материалу;
2. новой независимой проверки по официальному/первичному основанию;
3. новой независимой проверки числа/расчёта;
4. новой независимой ситуации, где надёжного основания нет.

Для C2 использовать вместе с ранее сохранённым evidence `M03-L02-C02`; второй сервис повторно не проходить.

## 1. Independence contract

До independent attempt автор/помощник не сообщает:

- метод;
- критерий;
- существенный claim;
- правильный источник;
- правильное число;
- ошибку;
- статус;
- правильное решение.

Допустима только technical/interface help.

Если содержательная подсказка реально повлияла на попытку, она = PRACTICE. Для level-3 evidence нужна новая ситуация под тем же Check ID.

Нельзя «восстановить независимость», попросив ученика повторить уже раскрытый ответ.

## 2. Stepik advisory

Stepik может позволить ранний переход к C01. Это не технический blocker.

Перед E01 learner-facing текст должен:

1. попросить сначала выполнить все три ситуации;
2. попросить сохранить естественный trace;
3. объяснить, что C01 содержит критерии, способные подсказать ход решения;
4. не изображать hard gate;
5. при содержательном загрязнении использовать alternate scenario.

Сам факт раннего чтения не является проступком. Вопрос только в том, повлияло ли содержание на решения.

## 3. Скрытая рубрика C01

### Ситуация 1 — внешний текущий факт

Подготовленное утверждение о часах Эрмитажа **намеренно не является авторским ground truth**. Часы могут меняться.

PASS оценивает процесс:

- ученик сам определил, какой факт существенно влияет на план;
- выбрал подходящее первичное/официальное основание без готовой ссылки автора;
- реально открыл источник;
- нашёл актуальные условия для нужного места/дня;
- не спутал поисковый сниппет, ответ ИИ или страницу-пересказ с содержанием первичного источника;
- статус и решение соответствуют фактически открытой информации на момент выполнения.

Если официальный источник недоступен, не засчитывать «похожий ответ другой модели». Использовать alternate R1.

### Ситуация 2 — число/расчёт

Контрольный исходник `A02`:

- групп: `6`;
- карточек на группу: `8`;
- запас: `0`.

Контрольный расчёт: `6 × 8 = 48`.

Подготовленный ответ ИИ использует неверный вход `7 групп` и арифметически корректно считает `7 × 8 = 56`.

PASS:

- ученик сам решил, какие данные существенны;
- открыл/использовал исходный материал;
- сопоставил входы, а не только пересчитал `7 × 8`;
- отдельно получил `48` обычным калькулятором;
- статус/решение связаны с расхождением входов.

Не выдавать PASS за случайно названное `48` без происхождения значений.

### Ситуация 3 — основания нет

Клуб «Лампа» вымышленный. По авторскому ключу надёжного подтверждения правила в условиях задачи нет.

Ожидаемая логика: уверенность модели и «обычно так» не создают основания. Допустимый итог — `данных недостаточно`, не обещать участникам разрешение как факт; при появлении реального ответственного источника проверить дальше.

Не требовать точной формулировки. Проверяется решение не выдумывать доказательство.

## 4. A1 / A2

A1 PASS:

- learner не приписывает подготовленной выдаче реальный поиск без следа;
- различает ситуацию 2, где ответ связан с переданным материалом, и ситуации, где исходная выдача не имеет подтверждённого внешнего основания;
- даже если AI-search использован для поиска ссылки, открывает внешнее основание отдельно.

A2 PASS:

- рассматривает выдачу как рабочую версию;
- сохраняет за собой выбор критерия/основания/статуса/применения;
- не применяет существенное из-за уверенного тона.

## 5. B9/B10/B11/C1 red-team

Не выдавать C01 PASS, если есть хотя бы один из случаев:

1. ссылка не открыта;
2. поисковый сниппет принят за основание;
3. вторая модель/самопроверка использована как единственное доказательство;
4. проверена только арифметика на неверных входах;
5. отсутствие опровержения превращено в подтверждение;
6. при `данных недостаточно` существенный результат применён как факт;
7. автор заранее назвал существенное/метод/источник/число/статус/решение;
8. ученик механически применяет один и тот же способ ко всем ситуациям;
9. решение рассказано задним числом без наблюдаемого действия;
10. re-check повторяет раскрытую структуру primary настолько близко, что learner может получить PASS простым воспроизведением недавней рубрики.

## 6. Re-check scenarios для C01

Используются только при содержательном загрязнении конкретной конструкции. Не показывать весь набор заранее.

Все re-check выполняются под **тем же** `M06-L04-C01`; новых Exercise/Check/Asset ID не создаётся.

Общая learner-facing инструкция для каждого re-check одна и та же:

> Решите ситуацию так, как считаете разумным, и сохраните естественный след своей работы.

До попытки нельзя добавлять «проверьте официальный источник», «сверьте входные данные», «здесь основания нет» или иной намёк на метод, ошибку, статус или действие.

### R1 — правило программного продукта, а не расписание учреждения

Learner-facing ситуация:

> Человек готовит короткую памятку по работе на общем компьютере. ИИ пишет: «Если скачать файл в приватном окне Firefox, после закрытия приватного окна сам скачанный файл удалится с компьютера, поэтому отдельно удалять его не нужно». Нужно решить, что из этого совета можно оставить в памятке.

Почему R1 действительно новая:

- область изменена с посещения учреждения на поведение программного продукта;
- существенное решение касается свойства функции и инструкции пользователю, а не времени визита;
- нет часов работы, времени прихода или конструкции «открыто до X»;
- learner должен заново определить существенный claim и подходящее основание.

Авторский контроль:

- не выдавать готовую ссылку и не называть заранее тип источника;
- не фиксировать текущую формулировку документации как вечный ground truth: оценивается фактически открытое актуальное первичное/официальное основание продукта;
- PASS требует реально открыть релевантное основание, найти относящийся фрагмент/условия, присвоить обоснованный статус и выбрать действие;
- ссылка, поисковый сниппет, пересказ ИИ или название сайта без релевантного содержания = FAIL.

Если подходящее первичное основание технически недоступно, этот re-check не заменяется второй моделью: используется другой низкорисковый внешний факт с иной содержательной структурой.

### R2 — пропущен обязательный компонент, а не изменено количество

Learner-facing пакет:

> Учебная заявка «Пульс»:
>
> - 3 стола;
> - для каждого стола нужно по 10 карточек-заданий;
> - дополнительно нужен один общий набор из 8 карточек с инструкцией;
> - запасные карточки не нужны.
>
> Подготовленный ответ ИИ: «3 × 10 = 30. Подготовьте 30 карточек — этого достаточно».
>
> Нужно решить, сколько карточек действительно требуется и можно ли использовать рекомендацию ИИ.

Почему R2 действительно новая:

- primary использует неверно перенесённое количество групп `6 → 7` при правильном умножении;
- R2 не меняет один вход на `N+1`: ИИ корректно считает часть задачи, но **игнорирует отдельный обязательный компонент**;
- learner должен заново определить, какие исходные условия входят в итог, а не просто искать расхождение одного числа.

Авторский контроль:

- контрольный итог: `3 × 10 + 8 = 38`;
- правильный итог сам по себе не даёт PASS;
- до попытки не говорить, что пропущены 8 карточек, не давать команду «сверьте входы» и не подсказывать формулу;
- PASS требует наблюдаемого происхождения используемых значений, отдельного вычисления и решения по результату;
- `30` после пересчёта `3 × 10`, случайно названное `38` или объяснение только после раскрытия рубрики без pre-rubric trace = FAIL / `NOT PROVEN`.

### R3 — новая техническая ситуация без заранее сообщённого отсутствия основания

Learner-facing ситуация:

> Для устройства «Орбита-X17» готовят короткую памятку перед выездным занятием. ИИ уверенно пишет: «Одного полного заряда хватает ровно на 48 часов непрерывной работы, поэтому запасное питание брать не нужно». Нужно решить, что делать с этим утверждением при подготовке памятки.

Почему R3 действительно новая:

- область изменена с правил клуба о поведении гостей на техническую характеристику конкретного устройства;
- задание не сообщает, существует ли документация, доступен ли первичный источник и можно ли надёжно подтвердить число `48 часов`;
- learner сам должен определить существенное, решить, какое основание понадобилось бы, попытаться установить его доступность, присвоить статус и выбрать действие.

Авторский контроль:

- `Орбита-X17` — вымышленное учебное устройство; надёжного первичного основания на заявленную характеристику в проектных материалах нет;
- **эту строку learner до попытки не видит**;
- learner-facing текст не должен содержать «правила нет», «источника нет», «подтверждений нет», «проверить невозможно», `данных недостаточно` или эквивалент;
- PASS требует наблюдаемой попытки самостоятельно определить, какое основание было бы подходящим, и установить, доступно ли оно; мгновенная догадка «наверное, данных недостаточно» без такого trace сама по себе не доказывает B10/C1;
- не считать отсутствие найденной страницы автоматическим доказательством ложности утверждения;
- ожидаемый безопасный результат при отсутствии найденного надёжного основания — статус `данных недостаточно`/эквивалент и отказ обещать характеристику как подтверждённый факт;
- если learner выдумал источник, принял отсутствие опровержения за подтверждение или применил число как факт без основания — FAIL.

### 6.1. Regression contract для любого R1/R2/R3

Перед выдачей re-check проверяющий обязан убедиться:

- learner не получает до попытки тип проверки;
- не получает правильный источник или готовую ссылку;
- не получает указание, какой элемент/число ситуации является ошибочным или требует проверки;
- не получает указание, где ошибка;
- не получает правильный статус;
- не получает следующее действие;
- новая ситуация отличается не только именами/числами, но областью, структурой решения или failure mode;
- substantive evidence возникает до раскрытия post-action rubric;
- post-action explanation объясняет ранее наблюдаемое действие, но не создаёт отсутствовавший выбор задним числом;
- отсутствие pre-rubric trace = `NOT PROVEN`;
- contaminated attempt нельзя восстановить повторением уже раскрытого ответа.

False PASS по-прежнему включает:

- ссылку без открытия;
- сниппет вместо основания;
- self-check ИИ;
- согласие второй модели;
- официальный сайт без релевантного фрагмента;
- арифметику без проверки происхождения/полноты входных данных;
- случайно названный правильный итог без основания;
- `не опровергнуто` → `подтверждено`;
- применение при `данных недостаточно`;
- рассказ задним числом;
- механический повтор раскрытого решения.

## 7. C02 — B12 level 3

PASS требует **фактического** применения пригодного результата новой безопасной ситуации.

Допустимый trace:

- обновлённая учебная заметка;
- короткий безопасный план;
- текст памятки, реально перенесённый в отдельный документ;
- иной малый артефакт, который завершает исходную микрозадачу.

FAIL:

- результат остался только в AI-chat;
- ученик пишет «мог бы применить»;
- применена существенная часть при `данных недостаточно`;
- артефакт создан, но никак не связан с проверенным результатом.

`A03` открывается после выбора и действия, чтобы форма не превращалась в pre-action checklist.

## 8. C03 — C2 + C3

Техническая памятка про LibreOffice является новой содержательной областью относительно посещения, учебной печати и вымышленного клуба.

Автор не фиксирует заранее правильный статус фразы `Ctrl + Shift + S ... всегда ... на любой системе`: learner должен определить подходящее основание и условия сам. Текущая официальная документация может изменяться.

C2 PASS:

- learner переносит знакомый принцип проверки в новую область;
- действие существенно отличается от предыдущих примеров;
- вместе учитывается ранее сохранённое `M03-L02-C02`;
- не требуется повторно входить во второй сервис.

C3 PASS:

- 2–3 объяснения связаны с конкретными решениями, реально выполненными в C01/C02/C03;
- повтор формулы курса без связи с выполненной работой не засчитывается.

## 9. Privacy / safety

Реальные чувствительные данные не нужны ни в одной части.

Если ученик хочет приложить screenshot как evidence, он должен быть безопасным: без аккаунтных идентификаторов, чужих данных, приватной истории, токенов/QR/телефонов.

High-stakes реальные решения исключены.

## 10. Dynamic layer

Service Acceptance 2026-09-11 подтверждает внешний browser route B10 owner-observed. Конкретные страницы внешних организаций/продуктов динамичны.

Не превращать заранее найденную документацию в live acceptance и не замораживать текущие часы/shortcut/поведение продукта как вечный ключ.

Перед публикацией перепроверить только техническую достижимость обязательных внешних действий и актуальность learner-facing ссылок, если какие-либо ссылки будут добавлены при Stepik-сборке.
