# Проектная карточка `M05-L02` — Создайте и доработайте изображение для новой задачи

> Производственная спецификация самостоятельных B7/B8, не ученический текст.

## A. Идентификация
- `M05-L02` / M05 «Перенесите доработку на изображение»; тип: визуальный, самостоятельная проверка; v1.0.
- Exercises: `M05-L02-E01`, `M05-L02-E02`; Checks: `M05-L02-C01`, `M05-L02-C02`.
- Assets: `M05-L02-A01`, `M05-L02-A02`, `M05-L02-A03`.

## B. Функция урока
Ученик для новой цели **реально** создает изображение, затем берет существующий безопасный исходник, сам замечает несоответствие новому назначению, формулирует нужную правку и получает **отредактированную версию этого исходника**. Здесь B7 и B8 достигают уровня 3. Не входит зачет по готовой картинке, демонстрации преподавателя или новой генерации с нуля вместо B8.

## C. Компетенции
- B7 INDEPENDENT уровень 3 (`C01`).
- B8 INDEPENDENT уровень 3 (`C02`).
- C1/C2/C3 PRACTICE; B1/B3/B4/B5/B6 REUSE.
Допустима интерфейсная помощь и необязательная техническая проба на постороннем нейтральном изображении; если оба утвержденных маршрута недоступны, зачета нет.

## D. Результат
После урока ученик сможет **для новой цели самостоятельно сгенерировать изображение, затем определить нужную правку существующего исходника и реально отредактировать его**. Доказательство: собственное описание + живая первая версия + сформулированное изменение + исходник + отредактированная версия + сравнение.

## E. Входные требования
B1/B3/B4/B5/B6; базовые файловые действия M00. Умение заранее знать интерфейс генерации/редактирования **не является входным требованием**: до `E01` доступен `M05-L02-A03` с технической пробой на другой нейтральной картинке. До передачи исходника применяется B3. Нельзя сообщать ученику конкретную правку; после самостоятельного выбора правки техническую памятку можно открыть повторно только для механики.

## F. Технический маршрут
- **PRIMARY:** Алиса AI с реальной генерацией и редактированием загруженного исходника.
- **BACKUP:** GigaChat: генерация через Kandinsky; для B8 только подтвержденный инструмент **изменения фона**. Нельзя обещать произвольный edit в BACKUP.
- FusionBrain/Kandinsky — лишь дополнительный резерв 18+, не обязательный маршрут.
- Риск SERVICE/VISUAL/INDEPENDENCE: временная недоступность → переключение, не демонстрационный зачет и не оплата.
- [DYNAMIC] B7 PRIMARY Y4 `https://alice.yandex.ru/support/ru/assistant/chat/picture`; B8 PRIMARY Y5 `https://alice.yandex.ru/support/ru/assistant/chat/edit-photos`; BACKUP B7 G6 `https://giga.chat/help/articles/how-to-generate-images`; BACKUP B8 G7 `https://giga.chat/help/articles/background-remove`; загрузка изображений G5 `https://giga.chat/help/articles/gigachat-load-picture`. Официальные пользовательские инструкции повторно проверены 2026-09-22: Алиса описывает запуск генерации через инструменты чата/«Нарисовать картинку», редактирование через прикрепление JPEG/PNG и описание изменения; GigaChat подтверждает бесплатную генерацию, загрузку изображения и узкое удаление/замену фона. **Проверка на свежих реальных бесплатных аккаунтах в этой работе не проводилась** и остается acceptance-gate.

## G. Первое действие
До проверочной задачи новичок при необходимости проходит `M05-L02-A03`: на постороннем геометрическом примере запускает генерацию, сохраняет результат, выбирает сохраненное изображение как исходник, делает заметное пробное изменение и сохраняет обе версии. Уже умеющий ученик пропускает пробу. Затем по `M05-L02-A01` самостоятельно формулирует назначение/существенные требования и запускает **живую** проверочную генерацию. Safety до действия: не использовать чувствительные фото/документы; B3 до upload. Ориентир 3–6 мин. с технической пробой или ~3 мин. без неё.

## H. Exercises
### `M05-L02-E01`
Для новой цели самому описать и реально сгенерировать изображение. Ученик сам выбирает назначение и существенные требования. След — описание + живая первая версия. Техническая проба `A03` не засчитывается вместо E01.
### `M05-L02-E02`
После изменения требования к назначению самому определить нужную правку и **реально отредактировать существующий исходник**. После фиксации собственной правки можно использовать `A03` только как интерфейсную памятку. Если по новому назначению learner не может честно назвать осмысленную правку, раннее раскрытие/подсказка загрязнили выбор или выбранный разумный edit технически не исполним, используется staged recovery: learner сначала создаёт и сохраняет новый широкий safe source без знания будущего назначения; только затем получает small-square reuse purpose, сам фиксирует correction и выполняет real edit. BACKUP limitation не раскрывается как «правильная правка» до own choice.

## I. Checks
### `M05-L02-C01`
- **B7 level 3:** самому описать новую визуальную задачу и выполнить живую генерацию.
- **Зачет:** собственное описание отражает назначение/требования; новая генерация реально получена.
- **Непрохождение:** авторская/готовая картинка, техническая проба A03 или демонстрация преподавателя вместо собственной проверочной генерации.
- **Доказательство:** описание + реально сгенерированная первая версия.

### `M05-L02-C02`
- **B8 level 3:** на существующем безопасном исходнике самому распознать нужное изменение и выполнить живую правку.
- **Зачет:** именно исходник отредактирован; новая версия ближе к требованию; в BACKUP используется только реально доступная подтвержденная операция, если она соответствует самостоятельно выбранной правке.
- **Непрохождение:** новая генерация с нуля, демонстрация преподавателя, неподтвержденный edit или содержательная подсказка правки.
- **Доказательство:** исходник + формулировка изменения + отредактированная версия + сравнение.
Критическая safety-ошибка: передача недопустимого чувствительного изображения.

## J. Уменьшение поддержки
M05-L01 давал авторские версии и содержательную подготовку. `A03` перед E01 дает только механику интерфейса на другой нейтральной картинке и может быть пропущен. В проверке ученик сам задает требования, получает живой результат и сам диагностирует правку. Интерфейсная помощь допустима; название нужной правки до самостоятельного выбора делает попытку PRACTICE и требует другого исходника/ситуации.

## K. Объяснение решения
- Почему эти требования существенны для назначения?
- Какой недостаток исходника вы заметили сами?
- Почему выбранная правка улучшает соответствие новому требованию?

## L. Перенос
Новая визуальная цель и реальный исходник. Для C2 принцип «оценить → конкретно исправить → сравнить» переносится с текста на изображение, не сводясь к бренду/кнопке. Техническая проба отделяет знание интерфейса от содержательного выбора.

## M. Safety / Privacy
B3 до каждой загрузки. Разрешены безопасные собственные генерации или подготовленные нейтральные исходники. Реальные документы, чувствительные скриншоты и изображения, которые нельзя передавать сервису, запрещены. Сомнение → другой исходник.

## N. B9/B10/B11
N/A как факт-проверка; оценка визуального результата идет по назначению/критериям B5.

## O. B7/B8
B7 требует **живую новую генерацию** по проверочной задаче. B8 требует **реальный edit существующего исходника** и сравнение версий. M05-L01 и техническая проба A03 не дают зачет. Новая генерация с нуля не заменяет B8. BACKUP B8 не расширяется сверх подтвержденной доступной операции.

## P. F1
N/A; B7/B8 позже не навязываются финальной задаче, если она их не требует.

## R. Assets
- `M05-L02-A01`: карточка новой визуальной задачи, без готовой формулировки решения.
- `M05-L02-A02`: форма «первая версия → новое требование → изменение → сравнение».
- `M05-L02-A03`: learner-facing необязательная техническая проба на постороннем нейтральном изображении; объясняет запуск функции, сохранение, повторный выбор исходника и сохранение версий, не раскрывая решение E01/E02.
Живые проверочные изображения создает/редактирует ученик.

## S. Stepik mapping
Safety → при необходимости technical A03 **до E01** → live `E01/C01` → reveal new purpose + own correction recorded → при необходимости A03 только для mechanics → live edit `E02/C02` → при contamination/no-mismatch/unexecutable attempt staged recovery source-first → purpose/edit → возврат в C02 → optional post-action form. Обычный тест и A03 не заменяют generation/edit. UI динамичен и перепроверяется перед публикацией.

## T. Время
23–39 мин. для новичка с технической пробой и 21–34 мин. для уже знакомого с интерфейсом: ориентация/проба 2–6; практика 7–10; checks 4–6; перенос/объяснение 2–3; техника 3–5; ожидание генерации/edit 3–7. Длинный, но активный урок; пилот и acceptance критичны.
