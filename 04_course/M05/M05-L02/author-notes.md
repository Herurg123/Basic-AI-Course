# Author notes — M05-L02

> Не ученический материал. Используется для защиты самостоятельности B7/B8 и корректного BACKUP.

## 1. Порядок раскрытия A01 после D-2026-09-12-STEPIK-FLOW

`M05-L02-A01.md` является полным production-master одного Asset ID и не включается целиком в обычный learner-facing маршрут.

Для student-facing маршрута используются два staged view того же Asset ID:

- `M05-L02-A01-part1.md` — основной материал E01/C01;
- `M05-L02-A01-part2.md` — размещается следующим шагом после C01.

`part1`/`part2` не создают новые Asset ID.

Stepik может позволить ученику открыть Part 2 раньше. На hard gate не рассчитываем. Перед E01 даём явную рекомендацию сначала выполнить живую B7-попытку, сохранить исходный запрос и результат, затем переходить к Part 2; кратко объясняем, что ранний просмотр может подсказать направление будущей B8-правки и снизить ценность самопроверки.

Если ученик прочитал Part 2 заранее, это не является нарушением само по себе. Если содержательная информация из Part 2 могла повлиять на выбор B8, исходная B8-ситуация остаётся PRACTICE и используется alternate scenario из §5. B7 не аннулируется автоматически, если собственное описание и живая генерация наблюдаемы.

## 2. Что разрешено подсказывать

До самостоятельного решения можно помочь только технически:

- где открыть режим генерации;
- как загрузить/скачать безопасное изображение;
- где находится доступная функция редактирования;
- как перейти на утверждённый BACKUP.

Нельзя до решения ученика:

- назвать конкретную правку;
- сказать «уберите фон» / «смените фон»;
- дать готовый текст запроса на edit;
- создать изображение или выполнить edit вместо ученика.

После такой содержательной подсказки текущая B8-попытка остаётся PRACTICE; для level 3 требуется новая безопасная ситуация.

## 3. BACKUP B8

Нормативный BACKUP B8 узкий: реальное удаление/замена фона существующего исходника в GigaChat. Не расширять его до произвольного редактирования.

Основной сценарий A01 намеренно создаёт исходник с тёмным фоном, а затем меняет назначение так, что самостоятельное решение может быть реализовано background-edit. Автор не называет это решение ученику заранее.

Если ученик предлагает другую разумную правку, которую узкий BACKUP не умеет выполнять, **не объявлять её неправильной**. Техническая ограниченность резервного сервиса не должна искусственно сужать содержательно допустимые самостоятельные решения. Возможные действия автора: использовать PRIMARY, дать другой безопасный исходник/alternate scenario, где выбранное учеником изменение реально выполнимо утверждённым маршрутом, либо честно зафиксировать, что обязательное действие пока технически не завершено.

## 4. Evidence

B7: собственное описание + живая генерация.  
B8: исходник + собственно сформулированная правка + реально отредактированная версия + сравнение.

Готовые `M05-L01-A02` не являются evidence B7/B8. Новая генерация с нуля вместо изменения существующего исходника не является B8.

## 5. Recovery / alternate scenario для B8

Используется, если:

- ученик прочитал Part 2 до завершения/фиксации B7 и эта информация могла подсказать направление B8;
- автор содержательно назвал нужную правку;
- исходная B8-попытка иным образом загрязнена содержательной подсказкой.

Повторять B7 не нужно, если `C01` уже имеет собственное описание и живую генерацию без содержательной помощи.

### R-B8-PRIMARY — другое назначение существующего изображения

Использовать безопасный существующий исходник ученика, который ещё не редактировался в этой re-check попытке.

Новая ситуация для ученика:

> Теперь это изображение хотят использовать как небольшую иллюстрацию рядом со списком мероприятий. В уменьшенном размере главный игровой объект должен оставаться узнаваемым, а мелкие или второстепенные детали не должны мешать восприятию. Сами определите одно конкретное изменение существующего изображения, которое лучше приспособит его к новому назначению, и выполните реальное редактирование исходника.

Автор не называет, что именно менять. Ученик может выбрать разумное изменение композиции, деталей, текста, фона или другого элемента, если PRIMARY действительно позволяет выполнить выбранный edit.

### R-B8-BACKUP — если доступен только узкий background-edit

Автор подбирает другой безопасный существующий исходник, у которого окружающее оформление/фон реально мешает новому нейтральному назначению. Ученику сообщается **назначение**, а не решение. Например:

> Этот объект нужно использовать в нескольких макетах с разным оформлением. Главный объект должен сохраниться, а окружающее оформление не должно мешать его размещению. Сами решите, какое изменение нужно исходнику, и выполните его.

Нельзя говорить «смените/удалите фон». Если ученик предлагает иную разумную правку, которую BACKUP не умеет выполнить, она не считается ошибкой; нужен PRIMARY либо другой посильный исходник/сценарий. Зачёт не подгоняется под кнопку.

R-B8 использует тот же `M05-L02-E02 / C02`; новый Exercise ID, Check ID или Asset ID не создаётся.

## 6. Red-team против ложного PASS

Не выдавать B8 level 3, если:

- вместо edit выполнена новая генерация с нуля;
- правку назвал автор до решения ученика;
- есть только словесное описание предполагаемого edit без реально отредактированной версии;
- исходник и новая версия не позволяют наблюдать связь;
- ученик загрузил недопустимый чувствительный материал;
- ранний просмотр Part 2 явно подсказал решение, но re-check не проведён.

При этом отсутствие технического hard gate Stepik само по себе не является FAIL по `D-2026-09-12-STEPIK-FLOW`.
