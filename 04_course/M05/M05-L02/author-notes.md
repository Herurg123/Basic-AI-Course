# Author notes — M05-L02

> Не ученический материал. Используется для защиты самостоятельности B7/B8 и корректного BACKUP.

## 1. Порядок раскрытия A01

`M05-L02-A01.md` является полным production-master одного Asset ID и **не выдаётся ученику целиком до C01**.

Для student-facing маршрута используются два staged view того же Asset ID:

- `M05-L02-A01-part1.md` — до E01/C01;
- `M05-L02-A01-part2.md` — только после фиксации E01/C01.

В Stepik и pilot эти части публикуются разными шагами. `part1`/`part2` не создают новые Asset ID.

## 2. Что разрешено подсказывать

До самостоятельного решения можно помочь только технически:

- где открыть режим генерации;
- как загрузить/скачать безопасное изображение;
- где находится доступная функция редактирования;
- как перейти на утверждённый BACKUP.

Нельзя до решения ученика:

- назвать конкретную правку;
- сказать «уберите фон» / «смените фон»;
- дать готовый текст запроса на edit;
- создать изображение или выполнить edit вместо ученика.

После такой содержательной подсказки текущая попытка остаётся PRACTICE; для level 3 требуется новая безопасная ситуация.

## 3. BACKUP B8

Нормативный BACKUP B8 узкий: реальное удаление/замена фона существующего исходника в GigaChat. Не расширять его до произвольного редактирования.

Сценарий A01 намеренно создаёт исходник с тёмным фоном, а затем меняет назначение так, что самостоятельное решение может быть реализовано background-edit. Автор не называет это решение ученику заранее.

Если ученик предлагает другую разумную правку, которую узкий BACKUP не умеет выполнять, не объявлять её неправильной. Если PRIMARY недоступен, для зачёта нужен другой безопасный исходник/сценарий, где собственный выбор ученика технически выполним утверждённым BACKUP.

## 4. Evidence

B7: собственное описание + живая генерация.  
B8: исходник + собственно сформулированная правка + реально отредактированная версия + сравнение.

Готовые `M05-L01-A02` не являются evidence B7/B8.
