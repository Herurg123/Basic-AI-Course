## 5. M04 — педагогическая траектория

### M04-L01

Поддержанная работа по безопасному учебному файлу:

`безопасный asset → собственная конкретная задача → ответ → самостоятельный выбор существенного утверждения → реально открытый исходник → конкретный фрагмент → статус → решение`.

A02 остаётся авторским ключом и не подсказывает ученику нужный фрагмент до попытки.

### M04-L02

B3 выводится на уровень 3 до работы с собственным материалом.

Ключевой порядок защищён:

`понять задачу → решить, что нужно/допустимо → обезличить/заменить/отказаться → только потом передавать`.

E02 меняет тип информации с текста на визуальный asset. Неспособность новичка технически закрасить изображение не вынуждает к рискованному upload: допустим безопасный пересказ или отказ, потому что редактирование изображения здесь не является компетенцией урока.

### M04-L03

B4 достигает уровня 3 на **собственном** нейтральном материале, выбранном/созданном учеником. Готовый asset курса не засчитывается.

B10 уровня 3 частично доказан по собственному материалу. Интерфейсная помощь разрешена; содержательный выбор материала, задачи, утверждения или основания делает попытку тренировочной.

## 6. M05 — педагогическая траектория

### M05-L01

Подготовленные авторские версии используются только для переноса цикла:

`назначение → требования → оценка → конкретный недостаток → конкретная правка`.

Ни одна авторская картинка не засчитывает B7/B8.

### M05-L02

B7 и B8 имеют отдельные observable evidence:

- B7: собственное описание + реально сгенерированное изображение;
- B8: существующий исходник + самостоятельно сформулированная правка + реально отредактированная версия + сравнение.

Новая генерация с нуля не заменяет B8.

Part 2 задачи открывается только после фиксации B7. Авторская заметка запрещает называть конкретную правку до решения ученика.

BACKUP B8 не расширен: GigaChat используется только в подтверждённом узком сценарии реального удаления/замены фона. Если ученик предлагает другую разумную правку, техническое ограничение BACKUP не превращает её в «неправильный ответ».

## 8. Privacy / safety

- M04-L01 использует только безопасный фиктивный asset.
- M04-L02 проверяет решение B3 **до** передачи на двух типах информации.
- M04-L03 требует B3 до собственного материала; сомнение означает заменить материал.
- M05-L02 запрещает чувствительные фото, документы и скриншоты до live upload/edit.
- Возраст не превращён во внутренний gate; пользователь следует текущим правилам самой платформы.
