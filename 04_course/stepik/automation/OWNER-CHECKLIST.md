# Owner checklist: текущий безопасный маршрут автоматизации Stepik

Этот список предназначен владельцу курса. Automation-чат должен выполнять всю техническую подготовку сам и запрашивать только следующее действие, которое действительно нельзя сделать через доступное подключение.

## Текущее подтверждённое состояние

Рабочий черновой курс проекта:

- `course_id=299189`;
- курс непубличный;
- в нём уже существуют все 9 разделов и все 21 урок;
- M00-L01 и M00-L02 вручную собраны и защищены как READ-ONLY golden sample;
- остальные уроки уже существуют как skeleton, поэтому **создавать оставшиеся 19 уроков вручную или автоматически не нужно**;
- live inspect run `34807212134` подтвердил сохранённый golden profile без blockers.

`course_id` уже задан как значение по умолчанию в GitHub Actions. Вспоминать и вводить его при каждом запуске не требуется.

## OAuth и секреты

OAuth application уже создана владельцем. GitHub Actions Secrets уже используются под именами:

- `STEPIC_CLIENT_ID`;
- `STEPIC_CLIENT_SECRET`.

Не присылать в ChatGPT, issue, PR или лог:

- `client_secret`;
- access token;
- пароль;
- cookies.

## Следующее действие владельца: первый ограниченный write-test

После того как PR с `content-test-one` прошёл CI, критическую проверку и вошёл в `main`, владелец запускает:

`GitHub → Actions → Stepik Uploader → Run workflow`

Параметры:

- branch: `main`;
- mode: `content-test-one`;
- course_id: оставить значение по умолчанию `299189`;
- `confirm_write`: **включить**.

Это уже не READ-ONLY запуск. Он имеет право записать содержание **только в существующий M02-L01**. Golden M00-L01/M00-L02 и остальные уроки этим режимом не изменяются.

После запуска владелец возвращает automation-чату только URL workflow run. Никаких секретов или экспортов вручную передавать не нужно.

## Что делает `content-test-one`

Первый write-test выбран на M02-L01, потому что этот урок:

- не golden;
- не independence-sensitive;
- не F1-sensitive;
- уже существует в Stepik на точной позиции;
- содержит только стандартную skeleton-заглушку;
- использует Markdown helper asset, который можно безопасно встроить в learner-facing текст без ручной загрузки binary file.

Перед первой записью automation ещё раз читает курс, проверяет golden profile, target lesson, title/position и текущее содержимое. Любое неожиданное состояние становится blocker.

После каждого PUT/POST выполняется отдельный read-back. Write-запросы автоматически не повторяются. `DELETE` отсутствует.

## Проверка идемпотентности

После успешного первого write-test потребуется **второй запуск того же `content-test-one`** с теми же параметрами.

Ожидаемый результат второго запуска:

- `NOOP_ALREADY_MATCHES`;
- 0 новых steps;
- 0 обновлений;
- тот же набор Stepik step IDs.

Только после этого можно считать техническую идемпотентность тестового маршрута подтверждённой.

## Визуальная проверка M02-L01

После первого успешного API write владелец должен открыть M02-L01 в Stepik глазами ученика/автора и проверить:

- порядок всех шести шагов;
- читаемость текста;
- наличие обеих учебных ситуаций;
- рабочие ссылки на Алису AI / backup;
- что шаг проверки действительно отображается как свободный ответ;
- что в урок не попали производственные комментарии, Asset/Exercise/Check ID или другой author-only текст;
- что структура урока соответствует production `lesson.md` и `stepik-plan.md`.

API read-back подтверждает техническую запись, но не заменяет эту визуальную проверку.

## Stepik Files на следующих этапах

Для binary assets стабильный официальный upload/list API пока не подтверждён. Поэтому основной fallback остаётся `manual-stepik-files`.

Когда automation дойдёт до первого урока с обязательным binary asset, он должен сначала выдать **точный список конкретных файлов и Lesson ID**. До этого ничего дополнительно загружать в Stepik Files не нужно.

После ручной загрузки владелец возвращает только обычные ссылки `Скопировать ссылку`; URL не конструируются по догадке.

## Что владелец сейчас НЕ должен делать

Не нужно:

- создавать новые modules/lessons;
- исправлять skeleton-заголовки вручную;
- копировать learner-facing содержание в остальные уроки;
- загружать все assets заранее;
- менять два golden lessons;
- удалять placeholder steps;
- присылать OAuth secrets;
- запускать массовую публикацию.

Массовый upload останется заблокирован до успешного одного write-test, его повторного no-op запуска и человеческой визуальной проверки. Серверное `200/201` всё ещё не сертификат педагогического здравомыслия, как бы удобно это ни было для цивилизации.
