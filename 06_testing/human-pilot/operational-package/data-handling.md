# Data Handling — Human Pilot

## 1. Принцип

Собирать минимально достаточное evidence действия, а не максимальный объём данных о человеке.

## 2. Идентификаторы

- pilot-data использует только Participant ID `P01`, `P02` ...;
- recruitment может временно использовать Candidate ID `C01` ...;
- связка ID ↔ контакт участника, если она нужна для организации сессии, хранится отдельно от GitHub и исследовательских таблиц;
- в GitHub не помещаются подписи, реальные имена, email, телефоны или аккаунтные идентификаторы участников.

## 3. Что разрешено фиксировать

- wave/session/Participant ID;
- тип устройства, браузер, PRIMARY/BACKUP route;
- timestamps и длительности;
- Lesson/Exercise/Check ID;
- intervention N/P/T/C/S;
- PASS/FAIL/PRACTICE-CONTAMINATED/NOT REACHED;
- безопасное краткое описание действия;
- redacted artifact или локальная ссылка/ID на безопасное хранилище, если артефакт нужен;
- факт открытия источника, edit, application;
- issue/retest metadata.

## 4. Что не коммитится в GitHub

- реальные имя, email, телефон, адрес;
- логины, пароли, cookies, токены, QR, одноразовые коды;
- финансовые реквизиты;
- медицинские/юридические и иные чувствительные персональные сведения;
- полные приватные переписки;
- конфиденциальные рабочие документы;
- raw screen/audio recordings;
- содержимое реальной F1-задачи, если для evidence достаточно типа действия и redacted trace.

## 5. Redaction before storage

Перед сохранением observer/moderator обязан спросить:

1. Нужен ли сам контент для доказательства проверяемого действия?
2. Можно ли доказать действие метаданными или кратким описанием?
3. Можно ли убрать имена, адресатов, номера, названия организаций и другие идентификаторы?
4. Не превращает ли сохранение evidence безопасную задачу в privacy-риск?

Если достаточно факта действия, хранится факт действия.

## 6. Записи экрана/голоса

Запись допустима только при отдельном согласии. До записи организатор определяет вне этого репозитория:

- хранилище;
- список лиц с доступом;
- срок удаления;
- способ удалить запись по принятой процедуре.

Сырые записи не добавляются в обычную Git-историю.

## 7. Evidence actual application

Для B12/F1 не требуется копировать личное содержимое. Допустимы:

- наблюдаемое действие + тип применения;
- redacted screenshot без адресата/личного текста;
- факт вставки/сохранения в нужный артефакт без самого приватного артефакта;
- минимальное безопасное описание завершённого действия.

Если применение нельзя доказать без нежелательного раскрытия, выбирается другая безопасная задача. Evidence rule не отменяет privacy.

## 8. Retention

Operational owner до Wave 0 обязан зафиксировать конкретные сроки хранения для контактной информации и, при наличии, raw recordings. Pilot CSV/MD в GitHub должны быть уже обезличены и не требовать последующей «чистки персональных данных» из Git history.
