# Moderator Guide — Human Pilot

## 1. Роль

Модератор проверяет, работает ли курс для новичка. Он не является репетитором во время независимой попытки и не обязан довести участника до правильного ответа.

Главный принцип:

> Лучше честно зафиксировать non-pass, чем получить красивый PASS с помощью модератора.

## 2. Перед первой сессией

Модератор обязан:

- прочитать Human Pilot Architecture v1.0;
- знать distinction `N / P / T / C / S`;
- пройти rehearsal на примерах ниже;
- знать, какие материалы learner-facing, а какие author-only;
- проверить, что author-only rubric/recovery не видны участнику раньше времени;
- иметь пустые observer/intervention/timing/evidence forms;
- убедиться, что consent оформлен;
- убедиться, что service preflight и Stepik staging readiness закрыты.

## 3. Taxonomy вмешательств

### N — NONE

Никакого вмешательства, влияющего на работу.

### P — PROTOCOL / NEUTRAL

Разрешено:

- «Продолжайте в своём темпе»;
- предложить перерыв;
- дословно повторить уже видимую learner-facing инструкцию;
- после stuck event спросить: **«Что сейчас мешает продолжить?»**

Нельзя «переформулировать понятнее», если новая формулировка сообщает содержательный класс действия.

### T — TECHNICAL / INTERFACE

Разрешено помогать с механикой, когда сама кнопка не является проверяемым навыком:

- где открыть вкладку/ссылку;
- как вызвать стандартный file picker;
- как скачать/найти файл;
- login/browser/device issue;
- переход на утверждённый BACKUP при hard service failure.

Нельзя под видом техники сообщать:

- какой материал нужен;
- какой источник выбрать;
- что именно проверить;
- какую правку сделать;
- какой следующий содержательный шаг выбрать.

### C — CONTENT

Content help есть, если модератор сужает содержательное решение, например:

- предлагает формулировку запроса;
- подсказывает цель/критерии/контекст;
- говорит, что именно обезличить;
- указывает недостаток первой версии;
- сообщает, что надо проверить, или предлагает источник;
- называет нужную правку изображения;
- выбирает следующий шаг;
- предлагает F1-задачу или способ её применения.

**Немедленное последствие:** текущая independent attempt получает `PRACTICE / CONTAMINATED`. Она не может получить independent PASS даже если участник дальше всё сделал правильно.

### S — SAFETY STOP

Немедленно остановить действие, если участник собирается реально:

- передать явно недопустимые/чувствительные данные;
- раскрыть секрет/пароль/код/финансовые реквизиты;
- выполнить high-stakes/опасное действие;
- применить существенный результат как подтверждённый при очевидно недостаточном основании;
- нарушить внешние правила сервиса.

Safety выше чистоты эксперимента. После stop фиксируется finding, даётся минимально необходимое safety-объяснение и используется предусмотренный безопасный recovery/practice route.

## 4. Stuck protocol

Не вмешиваться при первом молчании или паузе.

Нейтральная диагностика разрешена, когда:

- участник сам попросил помощь;
- сказал, что не знает, что делать дальше;
- трижды повторил одно и то же безуспешное техническое действие;
- возник hard interface/service failure;
- возник safety/privacy risk.

Первый вопрос один:

**«Что сейчас мешает продолжить?»**

Дальше:

- проблема механическая → T-help;
- проблема содержательная → не подсказывать ради сохранения PASS; зафиксировать non-pass/contamination и перейти к разрешённому practice/recovery только после фиксации результата попытки;
- проблема safety → S-stop.

## 5. Think-aloud

Не требовать постоянного «думайте вслух»: это само по себе может менять стратегию ученика. Допустимы краткие нейтральные вопросы после действия или в точке явного stuck event.

Для C3/F1 объяснение собирается **после** существенных решений. Вопрос не должен создавать действие задним числом.

## 6. Independent checks

Перед каждой independent attempt:

- проверить, не видел ли участник author-only answer/recovery;
- начать timing;
- зафиксировать все P/T/C/S вмешательства;
- не раскрывать rubric до того момента, который разрешён production sequence;
- если content contamination произошла, сразу пометить attempt и не «дотягивать» её до PASS.

Recovery используется только там и так, как предусмотрено production/архитектурой: содержательно другая эквивалентная ситуация, не косметическая замена.

## 7. B3 privacy

Нельзя спрашивать до действия: «Что здесь нужно удалить?» или перечислять чувствительные элементы.

Нужно наблюдать, выполнено ли реальное решение **до transfer**:

- допустимая передача как есть с обоснованием;
- фактическое обезличивание/замена;
- безопасный пересказ;
- отказ от передачи.

Фраза «я бы убрал имя» без выполненного действия не PASS.

## 8. B7/B8

B7: должна быть живая генерация по собственному описанию участника.

B8: должен существовать исходник и реальный edit этого исходника. Новая генерация «похожей картинки» не является edit.

Модератор не называет конкретную правку.

## 9. B10

Участник сам распознаёт существенное и реальную необходимость основания там, где это часть check.

Нельзя:

- выбрать источник за участника;
- считать показанную ИИ ссылку проверкой;
- считать self-check или второй ИИ внешним основанием;
- подсказать статус `подтверждено/не подтверждено/данных недостаточно`.

Technical help может помочь физически открыть браузер/ссылку, но не определить, **что** открыть.

## 10. B12

PASS только при фактическом действии, завершающем исходную задачу. «Скопирую потом», сохранённый ответ в чате или намерение отправить не считается применением.

## 11. F1

### До старта можно проверить только

- реальность задачи;
- посильность;
- безопасность / отсутствие high-stakes;
- допустимость материала.

### Нельзя

- предлагать конкретную задачу;
- выдавать шаги;
- напоминать рамку Task → ... как текущий маршрут;
- спрашивать наводяще про проверку до самостоятельного решения;
- указывать источник;
- говорить, что ответ нужно улучшить;
- предлагать уточнение/edit;
- выбирать способ применения.

### После действия можно спросить

- «Как вы поняли, что задача завершена?»
- «Что вы проверили и почему?»
- «Что осталось непроверенным?»
- «Где видно, что результат применён?»

Если content hint произошёл во время F1, текущая задача больше не может дать F1 PASS. Для новой чистой попытки участник сам выбирает **другую** новую реальную посильную задачу.

## 12. Rehearsal до Wave 0

Модератор классифицирует без подсказки минимум эти случаи:

| Реплика/действие | Ожидаемый класс |
|---|---|
| «Кнопка загрузки здесь» | T, если кнопка не проверяемый навык |
| «Добавьте срок, его не хватает» | C |
| «Что сейчас мешает продолжить?» после stuck event | P |
| «Поищите официальный источник» | C, если выбор типа основания является частью самостоятельной проверки |
| остановить отправку пароля | S |
| дословно повторить текст задания | P |
| «Попробуйте сделать фон светлее» | C |
| помочь открыть уже самостоятельно выбранную ссылку | T |
| «Вы уверены, что это проверено?» до самостоятельного решения | C |

Если модератор системно путает T/C или задаёт ведущие вопросы, он не готов к Wave 0.
