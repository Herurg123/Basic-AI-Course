# Evidence Aggregation Rules — Human Pilot

Некоторые финальные компетенции нельзя получить из одной строки одного Check ID. Этот файл запрещает ложный PASS при неполной сборке evidence.

## 1. Общий принцип

Итоговая компетенция = PASS только если присутствуют **все** компоненты, которые Coverage Matrix определяет как составное доказательство. Сильный поздний check не стирает отсутствие обязательного раннего evidence.

Post-hoc explanation не создаёт отсутствующий компонент.

## 2. B10 — четыре конструкции

Полный B10 level 3 складывается из:

1. `M04-L03-C02` — самостоятельная проверка по собственному материалу, частичный B10;
2. `M06-L04-C01` — внешний официальный/первичный источник;
3. `M06-L04-C01` — число/расчёт с проверкой исходных входов;
4. `M06-L04-C01` — ситуация без надёжного основания, где `данных недостаточно` допустимо.

### Нельзя ставить полный B10 PASS, если

- `M04-L03-C02` отсутствует/contaminated/not proven;
- источник в M06 не был реально открыт;
- арифметика пересчитана без проверки происхождения/полноты входов;
- отсутствие опровержения принято за подтверждение;
- self-check/вторая модель заменили реальное основание.

В `check-evidence-sheet.csv` ранний компонент хранится отдельной строкой `B10-material-partial`, а M06 — отдельной строкой `B10`. Итоговый отчёт обязан проверить обе строки и внутренние три конструкции M06 по observer evidence.

## 3. C2 — перенос между областями и интерфейсами

Финальный C2 level 3 складывается из:

1. `M03-L02-C02` — более раннее наблюдение, что участник распознаёт переносимое действие в другом интерфейсе, а не конкретную кнопку/бренд;
2. `M06-L04-C03` — перенос знакомого принципа в новую содержательную область.

`M03-L02-C02` остаётся contributing practice evidence, а не отдельным финальным level-3 C2. Но без него финальный C2 **не считается полностью доказанным** по действующей Coverage Matrix.

### Нельзя ставить C2 PASS, если

- ранний M03 evidence отсутствует/не достигнут/сводится к бренду или кнопке;
- M06 задача отличается только именами/числами;
- автор заранее назвал переносимый принцип;
- связь между двумя наблюдениями восстановлена только рассказом задним числом.

## 4. C3

C3 в `M06-L04-C03` требует объяснения причин **уже выполненных** существенных решений. Объяснение после рубрики не заменяет отсутствовавший выбор/проверку/действие.

## 5. F1

F1 имеет отдельную форму и не выводится автоматически из суммы предыдущих PASS. Предыдущие check results помогают интерпретировать progression, но `M07-L02-C01` требует собственного нового реального independent evidence и actual application.

## 6. Reporting

Wave summary и final report при агрегировании должны:

- хранить raw Check ID/dimension outcomes;
- отдельно вычислять composite B10 и C2;
- не считать `AMBIGUOUS`, `NOT REACHED` или `PRACTICE / CONTAMINATED` как PASS-компонент;
- при неполной составной компетенции указывать `NOT PROVEN / FAIL`, а не усреднять части.
