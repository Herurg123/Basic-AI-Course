# Service Preflight Checklist — Human Pilot

**Назначение:** проверить, что актуальный бесплатный технический маршрут реально выполняет обязательные действия курса и сегодняшняя поломка сервиса не будет ошибочно диагностирована как педагогический дефект.

Preflight не заменяет исторический Service Acceptance и не подтверждает будущую стабильность сервиса. Официальная документация, описание функции или наличие кнопки **не являются SERVICE PASS** без фактического действия.

## Служебная часть

- Date/time:
- Wave/session:
- Checked by:
- PRIMARY + surface/account condition:
- BACKUP + surface/account condition:
- Required payment: `NO / YES → BLOCKED`
- VPN/foreign card: `NO / YES → BLOCKED`
- Result: `PASS / PASS-WITH-ROUTE-SWITCH / BLOCKED`

Использовать тестовые безопасные данные, не данные участника.

## Route decision

- PRIMARY выполняет обязательное действие бесплатно → использовать обычный route.
- PRIMARY hard-fail, BACKUP **фактически** выполняет обязательное действие в допустимом бесплатном варианте → отметить `PASS-WITH-ROUTE-SWITCH`, заранее сообщить модератору только технический route.
- PRIMARY и BACKUP не дают обязательное действие → `BLOCKED`; затронутую human session не начинать как будто всё нормально.
- Документация обещает функцию, но live action не выполнен/не доказан → `BLOCKED / NOT VERIFIED`, а не PASS.

## PED-03 / B7: live generation

PASS только если в текущем аккаунте/поверхности сервис реально создал новое изображение по безопасному тестовому описанию.

Не засчитываются:

- официальная справка;
- ранее созданная картинка;
- демонстрационный screenshot;
- наличие пункта меню без получения результата.

## PED-03 / B8: real edit

PASS только если существует наблюдаемая цепочка:

`существующий исходник → конкретная правка → реально изменённая версия этого исходника`.

BACKUP засчитывается только в пределах реально подтверждённого edit. Если текущий BACKUP умеет только узкий вариант (например, background change), evidence и route decision должны назвать это ограничение явно.

Нельзя компенсировать отсутствие edit новой генерацией с нуля и затем считать B8 проверенным. Нельзя подгонять педагогически разумную правку под единственную доступную кнопку сервиса.

## Особо B10

Сам ИИ-сервис не является обязательным источником проверки. Нужен доступ к внешнему браузеру/реальному основанию. Наличие ссылки в ответе ИИ, уверенный тон или заявление модели «я проверил» не считаются preflight доказательством B10.

## Что не делать

- не покупать обязательную функцию ради pilot;
- не использовать VPN/иностранную карту как обязательный маршрут;
- не менять competency/check contract из-за сегодняшнего UI;
- не обучать участника новому содержательному обходу до старта independent attempt;
- не путать outage с course failure: outage фиксируется отдельно;
- не переносить старый SERVICE PASS на новый день/существенно изменившийся интерфейс без актуального preflight.

## PASS declaration

`PASS`/`PASS-WITH-ROUTE-SWITCH` разрешён только когда обязательные функции, включая PED-03 B7+B8, фактически выполнены на допустимом текущем бесплатном маршруте. Если B7 или B8 не подтверждены live action, общий service preflight для Wave 0 = `BLOCKED`.
