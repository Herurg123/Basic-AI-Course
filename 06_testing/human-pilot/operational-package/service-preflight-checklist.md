# Service Preflight Checklist — Human Pilot

**Назначение:** коротко проверить, что сегодняшняя поломка сервиса не будет ошибочно диагностирована как педагогический дефект курса.

Preflight не заменяет Service Acceptance и не подтверждает будущую стабильность сервиса.

## Служебная часть

- Date/time:
- Wave/session:
- Checked by:
- PRIMARY:
- BACKUP:
- Result: `PASS / PASS-WITH-ROUTE-SWITCH / BLOCKED`

Использовать тестовые безопасные данные, не данные участника.

## Route decision

- PRIMARY работает → использовать обычный route.
- PRIMARY hard-fail, BACKUP выполняет обязательное действие → отметить `PASS-WITH-ROUTE-SWITCH`, заранее сообщить модератору только технический route.
- PRIMARY и BACKUP не дают обязательное действие → `BLOCKED`; затронутую human session не начинать как будто всё нормально.

## Особо B8

BACKUP засчитывается только в пределах реально подтверждённого edit. Нельзя компенсировать отсутствие edit новой генерацией с нуля и затем считать B8 проверенным.

## Особо B10

Сам ИИ-сервис не является обязательным источником проверки. Нужен доступ к внешнему браузеру/реальному основанию. Наличие ссылки в ответе ИИ не считается preflight доказательством B10.

## Что не делать

- не покупать обязательную функцию ради pilot;
- не использовать VPN/иностранную карту как обязательный маршрут;
- не менять competency/check contract из-за сегодняшнего UI;
- не обучать участника новому содержательному обходу до старта independent attempt;
- не путать outage с course failure: outage фиксируется отдельно.
