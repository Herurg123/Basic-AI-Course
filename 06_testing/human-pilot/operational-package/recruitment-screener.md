# Recruitment Screener — Human Pilot

**Использовать до выдачи курса.** Не раскрывать author-only rubrics, recovery scenarios или F1 route.

## 1. Служебная часть

- Candidate ID: `C___`
- Screener date:
- Screener by:
- Decision: `ELIGIBLE / INELIGIBLE / HOLD`
- Planned wave: `W0 / W1 / W2`

Реальные имя, телефон, email и иные контактные данные не переносятся в GitHub pilot-data. Связка Candidate ID ↔ контакт, если она нужна организатору, хранится отдельно от исследовательских данных.

## 2. Предыдущий опыт с генеративным ИИ

Задать нейтрально:

1. Пользовались ли вы когда-нибудь ChatGPT, Алисой, GigaChat или другим ИИ, который создаёт текст/изображения?
2. Если да, примерно сколько раз и для чего?
3. Есть ли у вас привычный способ регулярно использовать ИИ в учёбе, работе или быту?
4. Проходили ли вы курсы/обучение по промптам, генеративному ИИ или нейросетям?
5. Пользуетесь ли вы генеративным ИИ профессионально или несколько раз в неделю?

### Fit rule

`ELIGIBLE` по опыту, если человек:

- раньше не пользовался генеративным ИИ; **или**
- имел примерно 1–2 случайные попытки;
- не имеет устойчивого собственного workflow;
- не проходил этот курс и не видел его author-only материалов.

`INELIGIBLE` для основного validation sample, если человек регулярно/профессионально работает с генеративным ИИ, уже знает структуру курса или видел rubrics/answer keys/recovery/F1 материалы.

Не пытаться «понизить» опыт кандидата ради квоты.

## 3. Базовая цифровая среда

Спросить, не обучая:

- основное устройство для прохождения: `PHONE / COMPUTER / OTHER`;
- ОС/тип устройства в свободной форме;
- основной браузер;
- может ли человек сам открыть ссылку в браузере;
- может ли выбрать/прикрепить файл обычным способом;
- может ли сохранить/найти скачанный файл;
- есть ли стабильный доступ в интернет;
- может ли создать/использовать аккаунт там, где это разрешено правилами сервиса.

Пробел, который по архитектуре должен закрываться M00, сам по себе не делает кандидата неподходящим. Фиксируется как baseline.

## 4. Доступ к внешним сервисам

Не обещать доступ. Проверить только условия среды:

- может ли кандидат законно и по правилам сервиса пользоваться PRIMARY/BACKUP;
- нет ли известного ограничения аккаунта/устройства, которое делает маршрут заведомо невозможным;
- кандидат не должен покупать подписку, использовать VPN или иностранную карту ради pilot.

Если PRIMARY недоступен, но утверждённый BACKUP доступен, кандидат может участвовать; route фиксируется.

## 5. Независимость от проекта

Подтвердить:

- кандидат не является автором/редактором курса;
- не участвовал в model/synthetic audits курса;
- не видел learner answers/author rubrics/recovery до теста;
- для Wave 2 не участвовал в Wave 0/1 и не получал материалы предыдущей версии.

## 6. Практическое разнообразие sample

При наборе Wave 1 обеспечить минимум:

- 2 участника с преимущественным PHONE route;
- 2 участника с преимущественным COMPUTER route.

Желательно иметь разные реальные мотивы: учёба / бытовые задачи / обычная работа. Это не статистическая квота аудитории.

## 7. Финальное решение

### ELIGIBLE

Кандидат соответствует novice definition и может пройти утверждённый маршрут без запрещённых условий.

### HOLD

Нужно решить чисто организационный/технический вопрос, не связанный с уровнем навыка. Причина записывается без чувствительных деталей.

### INELIGIBLE

Причина-код:

- `EXP-REGULAR-AI`
- `EXP-COURSE-SEEN`
- `EXP-AUTHOR/REVIEWER`
- `ACCESS-NO-VALID-ROUTE`
- `OTHER-NONFIT` + краткая безопасная причина

## 8. Запреты screener

- не давать мини-урок «чтобы проверить способности»;
- не показывать будущие задания;
- не объяснять правильный F1;
- не собирать чувствительные материалы кандидата;
- не обещать, что он обязан дойти до конца или получить PASS;
- не исключать неудобного новичка только потому, что он может показать слабое место курса.
