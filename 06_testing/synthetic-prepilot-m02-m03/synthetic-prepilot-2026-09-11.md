## 2. Четыре adversarial-профиля

| Профиль | Что проверялось |
|---|---|
| P1 — цифрово уверенный новичок | Склонность переусложнить первый запрос, собрать «идеальный prompt», механически перенести знакомый шаблон |
| P2 — низкая цифровая уверенность | Скрытые операции, непонятные переходы между asset/чатом/заметкой, зависимость от кнопок |
| P3 — буквальный пользователь | Риск выполнить только дословно названные действия, принять пример за единственно правильный ответ, пропустить самостоятельный выбор |
| P4 — «сделай лучше» / лишний контекст | Неконкретное уточнение, передача лишних данных, биографический overprompt, попытка пройти check словами вместо действий |

## 3. Результаты по урокам

### M02-L01 — PASS после walkthrough

Проверено:

- тема не выдаётся за задачу;
- нет формулы «роль + задача + контекст + формат + ограничения»;
- первая ситуация поддержана сильнее второй;
- во второй ситуации нет готовых критериев;
- критерии должны быть проверяемыми, но терминологического экзамена нет;
- B1/B5 остаются PRACTICE уровня 2, уровень 3 не заявлен;
- цифрово уверенный новичок не получает поощрения писать длинный prompt;
- буквальный пользователь видит раннее действие, но не получает скрытого правильного ответа.

**Риск:** ученик может выбрать слишком расплывчатый критерий.  
**Митигирование:** C01 требует объяснить, как по критерию определить пригодность; «чтобы было хорошо» без операционального смысла не проходит.

### M02-L02 — PASS после одной локальной правки

Первый walkthrough показал, что во второй ситуации исходная карточка содержала более одного потенциально существенного сигнала. Это могло сделать проверку двусмысленной: ученик мог выбрать «формат для телефона», хотя автор предполагал другой тип существенного условия.

**Исправлено:** карточка переработана так, чтобы единственным явно содержательным новым условием был предыдущий опыт аудитории книжного обмена; остальные детали не должны существенно менять короткое приглашение.

Проверено:

- privacy стоит до ввода;
- логика «только сведения, которые могут изменить результат» не превращается в «чем больше данных, тем лучше»;
- E01 даёт явно заметное условие другого типа — хранение без холодильника;
- meta-prompt введён как обычный способ продолжить диалог, а не как секретная формула;
- E02 не говорит «добавьте контекст», не называет недостающее условие и не приказывает «попросите ИИ задать вопросы»;
- C01 требует реального сообщения, изменённого результата и объяснения влияния;
- случайные подробности и чувствительные данные не получают PASS.

### M03-L01 — PASS

Проверено:

- подготовленная первая версия имеет один диагностируемый недостаток;
- недостаток не подписан в asset;
- упражнение не зависит от случайной live-ошибки модели;
- E01 позволяет выбрать тип действия из ограниченного знакомого набора, но не превращает набор в таблицу «если X → Y»;
- E02 требует собственное конкретное уточнение;
- «сделай лучше» не проходит;
- C1 не объявляется самостоятельным: урок остаётся INTRO/PRACTICE уровня 2.

### M03-L02 — PASS на уровне контент-контракта; A03 остаётся внешним asset blocker

Проверено:

- перед самостоятельной попыткой нет списка B1/B2/B5/B6 и нет подсказок «добавьте контекст / проверьте критерии / уточните»;
- A01 содержит новую ситуацию, но не готовую постановку, критерии или текст уточнения;
- существенное условие видно ученику как часть ситуации, но не названо «недостающим контекстом»;
- A02 заменяет только первую выдачу и не может использоваться для спасения проваленного B2;
- post-action C01 отделён от E01 и в Stepik-плане должен открываться только после завершения самостоятельной попытки;
- содержательная подсказка переводит текущую попытку в PRACTICE и требует новой ситуации;
- hidden re-check R1 в `author-notes.md` меняет предметную область и тип существенного условия;
- B12 остаётся PRACTICE и требует реального малого действия;
- C2 остаётся PRACTICE и не сводится к знанию бренда/кнопки.

**Локальная правка после red-team:** усилено evidence B1. Критерии должны существовать до решения о пригодности первой версии; критерии, придуманные только после открытия check, не доказывают самостоятельность.

**Внешний blocker:** `M03-L02-A03` пока не имеет реального PNG. Ветка содержит честный placeholder и точную owner capture-инструкцию. Сгенерированный fake UI не используется.

## 5. Cross-batch check M01-L02 → M02 → M03

### Переход M01-L02 → M02-L01

PASS. M01 уже ввёл критерий, рабочую версию и раннюю сверку основания. M02 не объясняет заново, что такое чат или почему ИИ может ошибаться; он усиливает постановку задачи и критерии.

### M02-L01 → M02-L02

PASS. Сначала ученик точнее описывает желаемый результат, затем сталкивается с условием, которое ИИ не знает. Контекст появляется как средство улучшить задачу, а не как обязательное поле каждого prompt.

### M02-L02 → M03-L01

PASS. После практики существенного условия ученик связывает уже конкретный недостаток ответа с разумным следующим шагом. Список вариантов ещё разрешён как временная опора.

### M03-L01 → M03-L02

PASS. Список действий исчезает. Новая ситуация требует самостоятельного выбора; техническая помощь остаётся доступной, но содержательный hint аннулирует level-3 attempt.

Не обнаружено:

- внезапного нового словаря;
- возврата к уровню M00;
- повторения M01-L01 под другим названием;
- скачка к самостоятельности без M02/M03-L01 practice;
- культа длинного первого prompt.

## 7. Риски для реального human pilot

Synthetic walkthrough не может подтвердить следующие вещи, поэтому их нужно отдельно наблюдать на настоящих новичках:

1. Не воспринимает ли ученик пост-action C01 M03-L02 как скрытую подсказку, если Stepik позволяет заранее пролистать следующий шаг.
2. Достаточно ли ясно различаются «критерий результата» и «условие ситуации» без лишней терминологии.
3. Не превращает ли часть новичков meta-prompt в новую магическую формулу, несмотря на предупреждение.
4. Не слишком ли заметно условие оборудования в M03-L02-A01 для реального level-3 B2.
5. Достаточно ли цифрово слабому ученику общей инструкции «сохраните в отдельную заметку» после M00-L03.
6. Работает ли реальный A03 как перенос принципа, а не как визуальная викторина про другой сервис.
7. Фактическое время прохождения и число повторных попыток.
