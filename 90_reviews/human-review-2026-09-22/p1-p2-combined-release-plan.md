# P1+P2 — объединённый release plan после двух human review

Дата: 23.09.2026

## Почему P1 и P2 объединены

Первый HUMAN VISUAL после P1 показал FAIL: визуальный контейнер существовал, но часть learner-инструкции оставалась внутри блока «Материал». Это доказало, что технический renderer и семантическая граница контента не могут проверяться независимо.

Поэтому следующий release выполняется как один пакет:

**P1 renderer + P2 learner-facing content/UX repair.**

Отдельного повторного P1 release перед P2 больше нет.

## Scope объединённого пакета

### 1. Renderer / граница материала

- inline Markdown вставляется в смысловой точке ссылки, а не в конец Stepik-шага;
- блок «Материал» визуально отделён;
- lesson-комментарий и действие ученика располагаются вне source-only материала;
- вложенные inline-материалы сохраняют verified rendering и не оставляют repo-relative ссылок;
- служебные placement tokens не могут попасть в learner-facing HTML.

### 2. Первый human review

Сохраняется весь ранее подготовленный P2 scope:

- убрать ложное «откройте/будет показано ниже»;
- убрать learner-visible `.md`;
- явно указывать место действия: Stepik / ИИ-чат / заметка / локальный файл;
- разделять работу ученика и работу ИИ;
- исправить внешние изображения/ссылки и скриншот Алисы;
- убрать непонятные «часть 1 / часть 2»;
- уточнить техническую помощь;
- сохранить ссылки автора;
- не обещать внешний автоматический verdict там, где его нет.

### 3. Второй human review

Дополнительно:

- M01-L01: показать целую цепочку «задача → ИИ → первая версия → оценка → уточнение → применение» и явно назвать продукт;
- M02-L02: явно назвать ожидаемый AI-output в обеих ситуациях;
- M03-L02: явно назвать роль ИИ в независимой/recovery-ситуации;
- M03-L02 transfer: сказать, что во второй сервис ничего отправлять не нужно; ученик наблюдает другой интерфейс и называет переносимое действие;
- при аудите ранних уроков отдельно проверять вопрос: «понятно ли, зачем здесь ИИ и что должно получиться?».

## Machine gates до Stepik

Перед live write обязательны:

1. CI всех uploader/content tests = SUCCESS.
2. Rendering всех 21 уроков = PASS.
3. Нет repo-relative learner links.
4. Нет leaked placement tokens.
5. Regression tests human-review semantic boundaries = PASS.
6. Stepik impact/sync plan не включает P3 topology changes.

## Model gates до merge/release

Для нового final head P2 заново обязательны отдельные:

- ORDINARY CRITIC: PASS;
- ZERO-LEVEL AUDIT: PASS;
- PEDAGOGUE AUDIT: PASS;
- final-head recheck после последних исправлений.

Старые PASS на предыдущем P2 head не переносятся автоматически на новый learner-facing head.

## Merge и private Stepik release

После всех gates P2 сливается в main. В main уже находится P1, поэтому следующий private release курса 299189 публикует P1+P2 вместе.

Курс перед write должен оставаться private.

## HUMAN VISUAL после объединённого release

Проверка обязательна на COMPUTER и PHONE.

Минимальный чек-лист:

1. M05-L01 / 6.1 / шаг 2: блок «Материал» заканчивается после фразы про дату/адрес/подробности; инструкция «после чтения…» находится **вне** блока.
2. M01-L01 / 2.1: сразу понятно, какой результат нужен от ИИ и что ученик делает после ответа.
3. M02-L02 / 3.2: в обеих ситуациях понятно, какой продукт должен дать ИИ.
4. M03-L02 / 4.2: в recovery-ситуации понятна роль ИИ; в шаге переноса понятно, что второй сервис не нужно запускать.
5. На телефоне граница блока не теряется при переносах строк и длинном тексте.

Только после COMPUTER PASS + PHONE PASS объединённый P1+P2 HUMAN VISUAL закрывается.

## P3

P3 остаётся отдельным следующим пакетом:

- линейные recovery-маршруты;
- новые физические tail-steps M04-L03 и M06-L04;
- отдельный guarded topology review перед live write.

Так как P2 head изменился после второго human review, stacked P3 перед продолжением должен быть reconciled/rebased на новый P2 head и повторно проверен по затронутым конфликтам.
