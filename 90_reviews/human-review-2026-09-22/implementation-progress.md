Это checkpoint (контрольная точка) для продолжения работы после возможной остановки. После каждого законченного подэтапа сюда заносится:

## Принятые владельцем решения

1. Инструкции ученику формулируются обычным человеческим языком. В практических местах должно быть однозначно понятно, **что делать и где делать**.
2. Внутри шага материалы для практики визуально отделяются от инструкции и пояснений. Выбран стиль: спокойная светлая карточка как в макете «вариант 1» + заметная вертикальная полоса как в «варианте 2».
3. Recovery/повторные попытки перестраиваются только вперёд: новая попытка получает свой последующий разбор; возвраты к предыдущему полю ответа убираются.
4. Фраза «можно спросить» без адресата не используется. Там, где техническая помощь действительно нужна, приводится понятный пример, кого/что можно спросить, без избыточного повторения по каждому шагу.
5. В финале курса блог `https://dzen.ru/rybv` позиционируется как источник бесплатных статей и видео для новичков; `https://rybalka.one/` — как сайт-визитка автора.
6. Новый снимок Алисы принят владельцем и уже заменён в `main` прямым commit `ec5a348...`. В этой ветке он считается входным состоянием и должен пройти итоговые learner-facing проверки вместе с изменениями.
7. Название/текст learner-facing «проверки» не должен обещать внешний вердикт, если Stepik фактически только принимает свободный самоотчёт/разбор.
