# Архитектура исправления learner-facing шагов — v1.0

**Дата:** 22 сентября 2026 года  
**Этап:** ШАГ 2 — implementation design, без production-изменения курса  
**Основание:** PR #116, merge `ad7f3645d4866fd1fb1569801f70a95b6b39e375`; Semantic Step Contract v1.0; Lesson Standard v1.5.  
**Source pin диагностированного ученического результата:** `d076dd06977ecc85db66abb1d3fc503eb7343d48`.

## 1. Цель и граница

Эта архитектура переводит 118 принятых находок Шага 1 в безопасный план производства. Она не является новым универсальным шаблоном шага и не меняет состав компетенций, 21 урок, уровни самостоятельности, F1 или продуктовую границу курса.

На Шаге 2 **не меняются** `lesson.md`, `stepik-plan.md`, learner assets, production renderer/uploader и Stepik. Здесь фиксируется только способ будущего исправления.

Главный критерий: абсолютный новичок понимает роль шага, применимые место/объект/результат/конец/сохранение/переход, но курс не делает за ученика содержательный выбор, который должен быть самостоятельным.

## 2. Архитектурный диагноз

Главный системный дефект находится не в 118 независимых фразах.

Текущий `general_content.py::_frame_step_card()` автоматически добавляет каждому шагу:

- `Зачем`;
- `Где и с чем`;
- `Что сделать`;
- `Готово, если`;
- иногда `Что сохранить` по наличию подстроки «сохран»;
- иногда `Что дальше` по эвристике внешнего действия.

Это напрямую противоречит принятому Semantic Step Contract: форма должна зависеть от функции, а неприменимые сведения не должны превращаться в пустые рубрики. Семейство `UNIVERSAL_FRAME` подтверждено на 133 из 148 шагов во всех 21 уроках.

Второй системный дефект — граница шага вычисляется из Markdown chunks и производственных markers, а не из законченной ученической функции. `CHUNK_BOUNDARY` затрагивает 63 шага в 19 уроках. Поэтому простое удаление рамки без исправления границ оставит часть курса семантически разорванной.

Следствие: production должен менять **и compiler contract, и адресные source/plan границы**. Один слой не может исправить другой автоматически.

## 3. Роли learner-facing шагов

Типы остаются ровно из Semantic Step Contract v1.0:

| Тип | Что обязан дать шаг | Что нельзя синтетически добавлять |
|---|---|---|
| EXPLANATION | конкретную мысль и связь с ближайшей работой | фиктивное действие, сохранение, «понятно = освоено» |
| DEMONSTRATION | ситуацию, показанное действие и последствие | выдавать показ за действие ученика |
| GUIDED_ACTION | действие, объект, достаточную поддержку, безопасный конец | лишний отчёт, обязательную бессмысленную доработку |
| INDEPENDENT_PRACTICE | новую ситуацию, нейтральные границы, честный конец попытки | метод, источник, статус, правку, скрытую рубрику |
| CHECK | какую прошлую работу проверяем, что предъявить, где ответить, что означает исход | создавать прошлое действие поздним рассказом |
| REFLECTION | короткое осмысление собственной работы | второй экзамен или новую обязательную практику |
| NAVIGATION | условие и реальный адрес перехода | содержательный выбор под видом навигации |
| TECHNICAL_SUPPORT | снятие технического препятствия | решение учебной задачи |
| RECOVERY | честную новую попытку после загрязнения/недоказанности | готовый запасной кейс или тот же раскрытый ответ |
| COMPOSITE | только реально связанные функции с единым понятным итогом | оправдывать случайный набор фрагментов |

Тип — авторская и тестовая семантика. Он **не означает обязательный видимый заголовок с названием типа**.

## 4. Новый compiler contract: authored semantic framing

### 4.1. Почему нужен opt-in

Мгновенная замена текущей рамки затронула бы все 21 урока одним изменением `general_content.py`. Это создаёт недопустимый blast radius и временно лишает ориентации шаги, в которых нужные сведения сейчас присутствуют только благодаря старой рамке.

Поэтому production вводит два режима на миграционный период:

1. **legacy-frame** — существующий результат для ещё не мигрированного урока;
2. **authored-semantic-v1** — новый режим, включаемый явно на уровне урока после исправления его source/plan.

Режим не должен определяться эвристикой текста. В `stepik-plan.md` используется одна не learner-facing директива уровня урока, например `learner-render-contract: authored-semantic-v1`. Точное машинное представление исполнитель может выбрать в существующем parser style, но оно должно быть единым, валидируемым и не появляться в HTML.

### 4.2. Что делает authored-semantic-v1

Compiler в новом режиме:

- сохраняет `Шаг N из M`;
- использует смысловое название текущей функции из authored source/явной production metadata;
- сохраняет authored learner-facing body и его порядок;
- определяет Stepik block type и технические dependencies;
- выполняет существующие verified-rendering, inline-source и asset contracts;
- **не генерирует** purpose/place/action/completion/save/navigation по ключевым словам;
- **не выводит** место из упоминания бренда, ссылки, слова «чат», «Stepik» или «сохранить»;
- **не создаёт** `Что сохранить` по regex;
- **не создаёт** `Что дальше` только потому, что найден внешний URL;
- **не объявляет** объяснение завершённым через «вам понятно».

Авторский source отвечает за те сведения, которые действительно нужны ученику.

### 4.3. Title contract

Для каждого мигрированного шага title должен описывать текущую роль, а не обещать весь урок. Предпочтение:

1. authored heading текущего semantic span;
2. явный production title для шага, если source heading отсутствует;
3. lesson title только если он действительно описывает первый шаг.

Нельзя автоматически считать lesson title корректным title первого шага.

## 5. Границы шага

Шаг считается семантически целым, если внутри одной предъявляемой единицы находятся все части, без которых текущая функция не завершена.

Обязательные правила:

- команда не отделяется от её условия, вопроса или объекта;
- причина нового действия находится до команды;
- встроенная learner-card является частью фактического шага и должна располагаться в момент потребности;
- completion не может стоять до inline material, необходимого текущему действию;
- post-action rubric не переносится до independent attempt;
- recovery не смешивается с обычным маршрутом так, чтобы выглядеть обязательным всем;
- объяснение и следующая практика могут быть разными шагами, если переход между ними однозначен;
- изменение числа/границ шагов требует повторной проверки всех ссылок, номеров, Stepik IDs/сопоставлений и соседних переходов.

Compiler не должен «лечить» плохую границу догадкой. Граница исправляется в `lesson.md` / `stepik-plan.md`, после чего проверяется конечный compiled HTML.

## 6. Место, объект, результат и completion

### Место

Место задаётся из фактической операции:

- Stepik — когда ученик читает или вводит короткий ответ в Stepik;
- ИИ-чат — когда там выполняется внешняя работа;
- локальный файл/изображение — когда объект реально хранится/редактируется локально;
- несколько мест называются по фазам, а не одной строкой «Где и с чем».

Если выбор инструмента/источника является проверяемой компетенцией, курс задаёт только допустимые границы и доступ, но не выбирает его за ученика.

### Объект

Не использовать «это», «материал», «результат ниже», когда возможны несколько объектов. Связь должна указывать на реальный объект: первая версия, собственный материал, сохранённое изображение, конкретная карточка и т. п.

### Результат

Для действия результат наблюдаем: ответ появился, файл действительно передан, существующее изображение реально изменено, утверждение сопоставлено с основанием, пригодный результат применён.

Для объяснения новый артефакт не изобретается.

### Completion

Completion относится к функции:

- действие — наблюдаемый конец;
- check — требуемые факты сопоставлены с реально выполненной работой;
- reflection — краткое осмысление, если ответ предусмотрен;
- explanation/demo — закончена смысловая единица, а не «доказано понимание».

Уже пригодный результат не заставляют переделывать. Непригодный результат нельзя фиктивно «применить».

## 7. Сохранение и natural trace

Сохранение требуется только когда объект:

1. нужен дальше;
2. нужен для возврата после паузы;
3. является естественным следом практики.

Нужно назвать объект, назначение и доступное место хранения. Не вводить обязательные приложение, имя файла или отчёт без причины.

Для independent work neutral trace можно попросить сохранять до попытки, но нельзя перечислять скрытые оцениваемые решения. Позднее пояснение может объяснить смысл уже существующего следа; оно не создаёт отсутствовавшее прошлое действие.

Отсутствие заранее предусмотренного поля не является автоматическим `NOT PROVEN`.

## 8. Переходы, technical support и recovery

### Переход

Явный переход нужен только при:

- реальном выходе из Stepik;
- условной ветке;
- зависимости от сохранённого объекта;
- новой попытке;
- нетривиальном возврате.

Обычное последовательное чтение использует навигацию Stepik без ритуальной фразы «идите дальше».

### Technical support

Помощь должна быть доступна **до или в точке сбоя**, а не в конце урока. Она:

- решает интерфейсную/операционную проблему;
- не выбирает содержательный следующий ход;
- при ссылке на единственную уже изученную памятку возвращает к конкретному прерванному действию;
- не заставляет всех проходить backup route.

Первое требование «новый/чистый чат» должно иметь техническое введение в M00; позже достаточно короткой ссылки/напоминания.

### Recovery

Нужно различать:

- действие подтверждено;
- есть естественный след, который можно пояснить позднее;
- ключевое прошлое действие действительно не доказано;
- попытка загрязнена содержательной подсказкой;
- работа ещё не завершена;
- технический сбой не изменил содержательную самостоятельность.

Новая самостоятельная попытка требуется при загрязнении или действительно недоказанном ключевом действии, когда прошлое нельзя честно восстановить. Она должна быть содержательно иной и собственной. Курс не выдаёт готовый новый кейс.

## 9. Independence invariants

До independent attempt разрешено уточнить:

- интерфейс;
- место предъявления;
- заданный объект;
- safety/privacy;
- способ сохранить естественный след;
- допустимые границы задачи.

Нельзя заранее дать:

- проверяемый метод;
- конкретный источник, если его выбор проверяется;
- недостаток;
- нужную правку;
- итоговый статус;
- скрытые категории рубрики;
- способ применения, если он должен выбираться учеником.

Особые invariants:

- M04-L03: самостоятельная сверка не получает готовый метод/основание;
- M05-L02: B8 — реальный edit существующего изображения, не regeneration;
- M06-L04: B10 — реальное открытое основание, не self-check ИИ;
- M07-L02: единственный F1; rubric/check после работы; реальное применение обязательно;
- M07-L01 остаётся rehearsal;
- M08 остаётся reflection, а не вторым экзаменом.

## 10. F1: SEM-117 / SEM-118

После F1 ученик должен уметь разобрать:

- собственный образ пригодности, существовавший до содержательной оценки;
- собственную оценку первой версии;
- фактическое применение;
- остальные применимые обязательные измерения по естественному следу.

Это **post-action** проверка. Нельзя заранее давать форму «цель → критерии → контекст → проверка → применение».

Если ранний natural trace подтверждает действие, позднее пояснение допустимо. Если ключевой выбор существует только как поздний рассказ, это `NOT PROVEN`, и нужен честный повтор на другой собственной задаче. Отсутствие отдельного формального поля само по себе не означает `NOT PROVEN`.

## 11. Layer ownership

| Слой | За что отвечает | Что не должен делать |
|---|---|---|
| `lesson.md` | learner-facing смысл, порядок, естественные переходы, условия, помощь | не хранить production-only IDs/рубрики |
| `stepik-plan.md` | production mapping, block type, author-only статусы, render contract, зависимости | не быть скрытым источником необходимого ученику объяснения |
| learner assets | материал, который ученик реально читает/использует | не раскрывать author-only key; не дублировать один inline-source |
| `general_content.py` | детерминированная сборка, spans, block types, минимальное framing | не сочинять педагогический смысл по regex |
| verified renderer | dependency resolution, materialization, HTML normalization | не исправлять семантику урока |
| tests | ловить структурные регрессии и известные invariants | не заменять zero-level semantic reading |

## 12. Production migration rule

Ни один урок не переводится в `authored-semantic-v1`, пока одновременно не выполнены:

1. адресные findings этого урока размечены на source/plan/asset/compiler;
2. source содержит достаточную естественную ориентацию без legacy frame;
3. границы шагов согласованы с plan;
4. итоговый compiled HTML проверен;
5. independence-sensitive шаги проверены отдельно;
6. применимые ZERO-LEVEL и PEDAGOGUE audits дали PASS.

После миграции lesson нельзя возвращать в legacy mode ради исправления текста.

## 13. STOP conditions будущего исполнителя

Production-исполнитель останавливает затронутый batch и не импровизирует, если:

- для ясности требуется раскрыть выбор, который матрица считает самостоятельным;
- два допустимых исправления меняют заявленную компетенцию или уровень;
- нужно добавить/убрать компетенцию, урок или самостоятельную проверку;
- recovery невозможно сделать честным без изменения критерия зачёта;
- требуется новый платный/недоступный обязательный маршрут;
- реальный source/asset не позволяет доказать нужное действие;
- меняется F1, B3, B8, B10 или B12 так, что их нормативное поведение становится неоднозначным;
- для M03-L02 повреждённый PNG нельзя заменить подлинным допустимым источником;
- обнаружен новый learner-facing diff вне scope batch;
- итоговый HTML расходится с утверждённым source/plan или показывает author-only материал.

Обычные редакторские решения внутри этого контракта не требуют владельца.

## 14. Что эта архитектура не закрывает

Она не закрывает:

- HUMAN VISUAL;
- SERVICE;
- Human Pilot / HUMAN VALIDATION;
- Wave 0;
- свежий Stepik read-back;
- реальные device/account ограничения.

После production merge эти gates должны выполняться по действующим readiness-документам.
