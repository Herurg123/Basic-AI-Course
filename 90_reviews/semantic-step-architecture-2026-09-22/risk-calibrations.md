# Risk calibrations and disputed cases

Этот файл фиксирует места, где массовое правило опасно применять механически.

## 1. Встроенная карточка

Inline learner card является частью фактического Stepik step. Нельзя объявлять действие отсутствующим только потому, что оно находится внутри карточки. Дефект возникает, если карточка стоит не в той фазе, раскрывает будущее или следует после completion.

## 2. Intentional learning errors

Намеренно неверный ответ/число/выдача, которую ученик должен обнаружить, не является авторской ошибкой. Production меняет её только если сломан сам учебный смысл или контрольный ключ.

## 3. Supported level 2 vs independent level 3

Guided/support practice не нужно искусственно очищать от помощи только потому, что позже навык проверяется independently. Снятие поддержки происходит в утверждённом месте, а не раньше.

## 4. M04-L02

- безопасность и общая команда карточки уже доступны;
- нельзя превращать локальные boundary defects в новый экзамен;
- recovery должен быть понятен без выдачи содержательного ответа;
- отсутствие отдельного формального поля не означает отсутствия действия.

## 5. M04-L03

Главный invariant: independent step проверяет собственный выбор существенного и способ сверки.

Нельзя до попытки:
- назвать правильный метод;
- назначить конкретное основание;
- выбрать утверждение/фрагмент;
- выдать итоговый статус.

Technical/interface help допустима. Уже подсказанную содержательно попытку нельзя переименовать в independent; нужна новая собственная ситуация.

## 6. M05-L02

- B7 = новая генерация;
- B8 = реальное изменение существующего изображения;
- если первая картинка уже пригодна, ученик не обязан выдумывать дефект;
- для проверки B8 допустима новая безопасная ситуация/назначение, где изменение действительно нужно;
- новое назначение не должно одновременно выдавать правильную правку;
- background removal/replacement support не превращается в ответ;
- recovery после content hint должна быть содержательно иной.

## 7. M06-L04

- поддержанная практика предыдущих уроков не равна independent B10;
- independent situation должна оставлять ученику выбор существенного, основания и статуса;
- категории/post-action check появляются после собственного действия;
- отсутствие подходящего основания допускает безопасный отказ;
- такой отказ не заменяет B12: ученик всё равно должен завершить и применить пригодный результат там, где это требуется;
- условный repeat не становится обязательным всем;
- новая ситуация после contamination должна оставаться новой.

LibreOffice нельзя автоматически объявлять «не новым» только из-за сходства общей операции с Firefox: новизна определяется изменением условий и требуемым переносом, а не названием приложения.

## 8. M07-L01

Это rehearsal / интегративная поддержанная практика. Не повышать её до второго independent exam и не убирать поддержку ради симметрии с F1.

## 9. M07-L02 / F1

Единственный F1.

До E01:
- own new real task;
- допустимые безопасные границы;
- neutral trace guidance;
- technical help boundary.

Нельзя:
- ready case;
- route/method;
- source type;
- needed correction;
- status;
- application method;
- detailed rubric.

После E01/application:
- A03/public self-check;
- собственные признаки пригодности до оценки;
- собственная оценка первой версии;
- остальные применимые обязательные измерения;
- natural trace можно пояснять позднее.

NOT PROVEN только если ключевой прошлый выбор не поддерживается ранним действием/trace и существует лишь в позднем рассказе. Отсутствие заранее названного поля не является FAIL.

Content hint that actually influenced attempt => PRACTICE and new substantively different own task.

## 10. M08

Reflection after F1. Не второй экзамен, не новая генерация, не обязательная покупка/сервис, не доказательство компетенций заново.

## 11. Damaged Alice PNG

Подтверждено повреждение canonical PNG на source pin. Это не является свежим наблюдением текущего published attachment.

Production:
1. найти/создать только подлинный допустимый screenshot реального интерфейса;
2. заменить canonical asset;
3. проверить decode/hash/materialization;
4. после release отдельно HUMAN VISUAL текущего learner UI.

Локальный decode PASS не закрывает live visual gate.

## 12. Service/tool failure

Неуспех автоматического инструмента прочитать Эрмитаж или иной внешний ресурс не доказывает универсальную недоступность ресурса ученикам. SERVICE verdict требует отдельного актуального service preflight по утверждённому маршруту.

## 13. CLEAN/POLISH

CLEAN не трогать без прямой зависимости от systemic compiler migration. POLISH исправлять минимально. Нельзя добавлять упражнения, отчёты или новые обязательные действия только ради «полноты стандарта».

## 14. Good/bad result branches

- good first result: не требовать бессмысленной доработки;
- bad result: не применять фиктивно;
- safe refusal: допустим как решение, но не завершает B12/F1 сам по себе;
- impossible safe completion: выбрать честный дальнейший путь, не менять задним числом задачу на «решить, отказаться ли».

## 15. Navigation can leak content

Ссылка/название инструмента/источника/места не автоматически нейтральны. Если competence проверяет выбор метода или основания, точный destination может подсказать ответ. В таких шагах navigation specifies access boundary, not substantive route.
