## 2. Точные требования к происхождению и безопасности

1. Сервис: для нового диалога/вложения **Алиса AI**, для условного резерва GigaChat — только при фактически проверенной необходимости; для переключения — открытый Stepik и выбранный чат. Устройство, ОС, браузер/приложение, язык интерфейса и **дата фактической проверки** обязательны в подписи/метаданных; дата имени файла сама по себе ничего не доказывает.
2. Реальный интерфейс, текущие подписи кнопок и состояния. Снимок не принимается, если демонстрирует недоступную/недействительную функцию, скрывает ключевую операцию или вместо реального UI является «художественным примером».
3. **Только безопасные учебные данные**: не показывать логины, имена аккаунтов, приватные сообщения/контакты, токены, номера телефона и файлы посторонних. При необходимости приватные зоны скрыть до передачи, сохранив возможность проверить саму кнопку/цепочку.
4. Отдельно подтвердить факт загрузки/сохранения того же файла `05_assets/M00/M00-L02/M00-L02-A01.docx`; ученик действительно прикрепляет DOCX, а текстовую копию использует только для просмотра, если документ не открывается.
5. Место активного учебного шага и повторный выбор того же источника должны быть различимы. Не делать кнопку «Назад» общим рецептом, если она может увести к прежнему экрану чата вместо нужного материала.
6. Скриншот — **не доказательство реального выполнения учеником**. После объяснения он выполняет настоящие действия: новый диалог (при необходимости), скачивание/прикрепление учебного файла, переход туда и обратно.
7. PNG должен читаться в нормальном размере на Stepik. Показать стрелкой реальную проверенную операцию и кратко подписать результат; не изображать на нём готовый запрос к экзаменационному примеру, проверочный статус или решение самостоятельной задачи.

## 4. Граница готовности, тесты и результаты

- **Сейчас:** доказан только актуальный диагностический запрос и существование текстовой памятки. **Не проверено:** реальные кнопки, мобильное поведение, наличие/расположение загрузки и переключение живого Stepik. Никакая иллюстрация не изготовлена.
- После получения снимков проверить фактические файлы **в удалённом GitHub именно на рабочей ветке**, прочитать их и сопоставить с настоящими версиями интерфейса. Только после этого разрешены подписи «на снимке ниже» и обязательная правка ученического текста.
- Далее выполнить офлайн-компиляцию всех напрямую затронутых шагов с фактическим встраиванием PNG, проверку ссылок, количество упражнений и без публикации Stepik.
- Для learner-facing PR необходимы **три отдельных заключения**: критик, `ZERO-LEVEL AUDIT: PASS`, `PEDAGOGUE AUDIT: PASS`; для функций кнопок и реальной удобности формальный модельный PASS не заменяет проверку живого UI.
- HR-002/003/007 **не закрывать**, пока не доказано, что конкретная техническая операция впервые выполнима по опубликованной помощи. Частичный текстовый прогресс отдельно отмечать.
- Если сервисы не допускают самостоятельной съёмки, владелец может предоставить реальные обезличенные скриншоты. Каждый запрос на GitHub upload указывает точную ветку и путь; скриншот, оставшийся только в чате, не считается файлом GitHub.

## 5. Что можно делать независимо

Без снимков можно подготовить и проверить устойчивые текстовые пояснения, **не ссылаясь на несуществующую иллюстрацию** и не обещая неизвестные кнопки. После PR, содержащего только это ТЗ, можно параллельно редактировать R04–R10 в отдельных ветках с соблюдением их методических gate. HR-006 и SEM-066 остаются отдельными решениями владельца, а не причиной объявить завершённым R02.
