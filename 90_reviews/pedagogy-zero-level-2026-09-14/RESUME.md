## Часть B — GitHub Actions / unit tests

### Первый прогон PR #59

Workflow `Stepik Uploader` run #45 завершился `failure` на unit tests. Structural dry-run был пропущен.

Единственный падающий тест:

`test_real_course_asset_sources_are_hashable_and_present`

Инвентаризатор ошибочно сообщил, что отсутствуют:

- `M00-L03-A02`;
- `M05-L02-A03`.

Физически оба файла существовали. Причина была инфраструктурной: `asset_inventory.py` предполагал, что любой Asset ID, упомянутый уроком, обязан лежать в папке этого же урока. После PED-01 и PED-03 появились законные cross-lesson reuse:

- M00-L02 ссылается на техническую памятку `M00-L03-A02`;
- M05-L01 заранее сообщает о технической пробе `M05-L02-A03` следующего урока.

Канонический manifest корректно собирает Asset IDs из learner-facing урока/Stepik-плана, поэтому дефект находился именно в физическом resolver инвентаризатора.

### Исправление CI-дефекта

Изменён только инфраструктурный слой, педагогические тексты при этом не менялись:

- `scripts/stepik_uploader/asset_inventory.py` теперь определяет физическую папку по самому каноническому Asset ID (`Mxx-Lyy-Azz`), а не по уроку-потребителю;
- добавлен регрессионный тест `test_cross_lesson_asset_id_resolves_to_owning_lesson_directory`.

Коммиты исправления:

- `313cdd7797a770a53a9d3ad88338bb68b7eb1c3a` — resolver cross-lesson assets;
- `6aada97a7ce2db4129426092569d434b5bff01fb` — регрессионный тест.

После исправления diff относительно `main` содержит только два дополнительных ожидаемых файла инфраструктуры: `asset_inventory.py` и его тест. Ветка остаётся `behind_by: 0`, merge-base совпадает с текущим `main`.
