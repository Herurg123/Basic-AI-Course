## 0. Как читать v1.2

Версия 1.2 изменяет только формулировки о необходимости авторизации в GigaChat. При конфликте формулировок v1.0/v1.1 с этим документом применяется v1.2.

## 1. Что изменилось

Ранее BACKUP-маршрут GigaChat описывался так, будто обычный consumer login через Сбер ID / телефон обязателен до любого действия.

Это больше нельзя считать универсальным правилом.

Актуальный consumer web-route GigaChat позволяет часть базовых действий выполнять без входа. При этом отдельные функции могут потребовать авторизацию. Поэтому курс не должен ни требовать вход заранее, ни обещать, что любое действие всегда доступно гостю.

## 2. Нормативный маршрут GigaChat

Для learner-facing инструкций действует следующий порядок:

1. Открыть [GigaChat](https://giga.chat/) и попробовать выполнить нужное действие.
2. Если действие доступно без входа, дополнительная авторизация не требуется.
3. Если именно для этого действия сервис просит войти, использовать обычный вход по правилам GigaChat.
4. Не обходить ограничения платформы и не создавать фиктивные аккаунты.
5. Не считать наличие гостевого текстового режима доказательством того, что без входа доступны загрузка файлов, генерация/редактирование изображений или другие расширенные функции: это проверяется в точке потребности.

Формулировка курса по умолчанию:

> «Откройте GigaChat и попробуйте выполнить нужное действие. Если сервис попросит войти для этого действия, используйте обычный вход по его правилам».

Для первого знакомства допустимо дополнительно пояснить:

> «Если сервис позволяет продолжить без входа, авторизация не нужна».

## 3. B0 и BACKUP

Актуальная трактовка BACKUP:

- BACKUP: GigaChat web;
- гостевой маршрут используется там, где нужное действие действительно доступно без входа;
- consumer login используется только когда сервис требует его для конкретного действия;
- обязательная платная подписка, VPN или зарубежная карта для базового маршрута по-прежнему являются блокерами;
- курс следует требованиям самой платформы и не учит их обходить.

## 4. Функции с отдельной проверкой

Наличие гостевого текстового диалога не переносится автоматически на другие функции.

Перед learner-facing обещанием конкретной возможности отдельно перепроверяются:

- загрузка документов и изображений;
- генерация изображений;
- редактирование изображений;
- сохранение истории/возврат к чату, если это требуется упражнением;
- иные действия, для которых интерфейс явно показывает требование входа.

Если функция требует входа, курс говорит об этом условно в момент потребности, а не превращает авторизацию в предварительное требование всего BACKUP-маршрута.

## 5. Подтверждение на дату обновления

Официальные consumer-источники GigaChat на 19 сентября 2026 года дают одновременно два важных сигнала:

- портал GigaChat предлагает вариант «Попробовать GigaChat без входа»;
- база знаний объясняет, что регистрация открывает использование без ограничений, а отдельные инструкции полного режима продолжают описывать вход через телефон / Сбер ID.

Источники:

- https://giga.chat/portal
- https://giga.chat/help
- https://giga.chat/help/articles/how-to-start-work-with-gigachat

Поэтому устойчивое правило курса — **не угадывать требование авторизации заранее, а следовать фактическому требованию сервиса для конкретного действия**.

## 6. Что не меняется

Это обновление не меняет:

- PRIMARY/BACKUP как архитектурный принцип;
- бесплатность обязательного маршрута;
- privacy/safety требования;
- запрет обхода правил сторонних сервисов;
- компетенции и учебную последовательность;
- Human Pilot и service-preflight gates.

Изменяется только неверная категоричность «GigaChat = сначала обязательный вход».
